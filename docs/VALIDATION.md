# گزارش آماده‌سازی انتشار

تاریخ: ۲۰۲۶-۱۱-۱۶ · نسخهٔ افزونه: `1.1.0`

این گزارش فقط بررسی‌های انجام‌شده در زمان آماده‌سازی مخزن را ثبت می‌کند و تضمین سازگاری با تمام فروشگاه‌ها نیست.

| بررسی | نتیجه |
| --- | --- |
| تست واحد PHP با PHPUnit 9.6.39 | ۶۵ تست و ۱۱٬۱۵۵ assertion موفق |
| تست پنل با Vitest 5.1.0 | ۲۷ تست در ۴ فایل موفق |
| بررسی نوع‌های TypeScript | موفق |
| ساخت پنل برای انتشار | موفق؛ خروجی JS و CSS ساخته و CSS به `#dsd-root` محدود شد |
| مجموعهٔ یکپارچه و بار روی WooCommerce و ۳۰۰۰ محصول | در این نوبت اجرا نشد؛ ادامهٔ تست‌ها طبق درخواست مالک متوقف شد |
| سازگاری اجرایی PHP 7.4 در کانتینر | در این نوبت اجرا نشد |

PHP محلی در این اجرا از نسخهٔ نصب‌شدهٔ میزبان استفاده کرد؛ اجرای تست روی آن جای اجرای مستقل PHP 7.4 را نمی‌گیرد. Node.js میزبان `24.9.0` بود: نصب وابستگی‌ها دربارهٔ حداقل نسخهٔ برخی وابستگی‌های تست هشدار داد، هرچند تست و ساخت پنل موفق شدند. نسخه‌های مناسب برای نصب جدید در README آمده‌اند.

ساخت Vite دربارهٔ استفاده از `__dirname` و سازگاری با بارگذار پیکربندی پیش‌فرض نسخهٔ اصلی آینده هشدار داد؛ ساخت فعلی موفق بود.

تصاویر و راهنمای PDF موجود، خروجی محیط آزمایشی قبلی پروژه‌اند. اعداد کارایی داخل آن‌ها و فایل‌های گزارش قدیمی، نتیجهٔ اندازه‌گیری مجدد این انتشار نیستند. گزارش‌های موقت تست، بستهٔ افزونهٔ شخص ثالث و وابستگی‌های نصب‌شده در Git منتشر نمی‌شوند.

## نوبت ۲۰۲۶-۱۱-۲۷ — خروجی اکسل و PDF گزارش کمپین

| بررسی | نتیجه |
| --- | --- |
| تست واحد PHP (PHP 8.3 و PHP 7.4 در کانتینر) | ۸۶ تست موفق؛ lint با PHP 7.4 موفق |
| تست پنل، TypeScript و ساخت | ۲۷ تست Vitest موفق؛ ساخت و محدودسازی CSS موفق |
| مجموعهٔ یکپارچه روی WooCommerce 10.3.5 و ۳۰۰۰ محصول | ۱۶ از ۲۰ سناریو موفق، از جمله `s20` (گزارش اکسل/PDF) |
| `s16`، `s17`، `s18` | ابتدا ناموفق (روی کد پیش از این تغییر هم)؛ ایراد در خود تست‌ها بود و پس از اصلاح هر سه موفق‌اند |
| `s19` | اجرا نشد: بستهٔ WP Rocket دریافتی نسخهٔ فروشنده (راست‌چین) با فایل رمزشدهٔ ionCube بود؛ بستهٔ رسمی wp-rocket.me لازم است |

اصلاح تست‌ها: `s16` خطای مرگبار واقعی (تمام شدن حافظه) شبیه‌سازی می‌کند؛ فراخوانی تابع ناموجود در PHP 7+ فقط خطای قابل‌گرفتن است و موتور آن را برای هر محصول می‌گیرد و دوباره امتحان می‌کند. `s17` تاریخ شمسی درست را می‌فرستد (۲۱ دی ۱۴۷۷ = 2099-01-10؛ تبدیل PHP با date-fns-jalali پنل در همهٔ روزهای ۱۹۲۵ تا ۲۱۲۵ یکی است). `restore()` کلید `cache_compat` را هم می‌نویسد تا `s18`/`s19` بتوانند آن را تغییر دهند. `s19` پیش از نصب، بستهٔ رمزشده را رد می‌کند و اگر افزونه بارگذاری وردپرس را خراب کند، بدون بارگذاری آن غیرفعالش می‌کند.

فایل اکسل خروجی با openpyxl و LibreOffice باز و خوانده شد؛ صفحهٔ PDF با Chromium چاپ و بررسی شد.
